# Workflow: iniciar trabalho de UI com interface-design

Use quando o usuário começar uma tarefa grande de UI de produto (dashboard, app, painel) e você quiser alinhar ao fluxo completo da skill — ou quando pedirem explicitamente "init" / começar com craft.

## Leitura obrigatória

Antes de escrever código, ler por completo o arquivo **`SKILL.md`** na raiz desta skill (pasta `interface-design` dentro de `.cursor/skills/`). Lá estão fundamentos, princípios, checks e fluxo.

**Escopo:** dashboards, apps, ferramentas, admin. Não landing/marketing (redirecionar mentalmente para fluxo de frontend/marketing se for o caso).

## Intent primeiro

Responder (em conjunto com o usuário se necessário): quem é o humano, o que precisa realizar (verbo concreto), como deve parecer (linguagem específica, não "clean/modern" genérico).

## Antes de cada componente

Declarar intent, paleta, depth, superfícies, tipografia, spacing — conforme o template no `SKILL.md`.

## Comunicação

Não anunciar modos. Entrar no trabalho com sugestões e raciocínio.

## Fluxo

1. Ler `SKILL.md` (sempre)
2. Se existir `.interface-design/system.md`, aplicar decisões lá
3. Se não existir, explorar domínio, propor direção, confirmar, construir, rodar checks do mandato, oferecer salvar padrões

## Ao terminar

Oferecer salvar em `.interface-design/system.md` quando fizer sentido.
