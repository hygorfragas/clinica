# Workflow: crítica de craft pós-build

Use quando o usuário pedir crítica de interface, revisão de craft, "interface-design critique", ou refinamento após uma primeira versão.

Conteúdo de referência detalhado: `references/critique.md` na mesma skill.

## Processo

1. Abrir o que foi construído (arquivos/componentes relevantes)
2. Avaliar: composição, craft (tipografia, superfícies, estados), conteúdo coerente, estrutura CSS (hacks vs. solução limpa)
3. Identificar onde houve default em vez de decisão
4. Reconstruir as partes problemáticas a partir da intenção — não apenas patches cosméticos
5. Evitar narrar o processo de crítica em excesso; priorizar o resultado corrigido

## Lembrete

O primeiro build costuma ser "correto"; este fluxo puxa em direção a "com craft", conforme o protocolo em `references/critique.md`.
